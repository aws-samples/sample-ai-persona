{# Form validation error components. Errors that the user can fix by correcting input (ErrorKind.VALIDATION / CAPACITY) are shown next to the relevant field without removing the form. The message is resolved by the catalog in web/error_messages.py and received as `form_error`. Macros provided: - form_error_summary(form_error, error_field) ... summary at the top of the form - field_border(error_field, field_name) ........ border classes for an input - field_error(error_field, field_name, form_error) ... error shown right below each field `error_field` is the field key the error refers to (for example "name"). It is set only when the Manager puts it in context["field"]. When the field cannot be identified, only the summary is shown (a red border on an unknown field would mislead). Note: writing Jinja tag syntax inside this comment makes it parse even though it is a comment and raises an undefined error. See the call sites in templates for usage. #} {# Summary at the top of the form. When the field cannot be identified, the error appears only here. #} {% macro form_error_summary(form_error, error_field) %} {%- if form_error and not error_field %}

{{ form_error }}

{%- endif %} {% endmacro %} {# Border classes for an input; red only on error. #} {% macro field_border(error_field, field_name) %} {%- if error_field and error_field == field_name -%} border-red-400 focus:ring-red-500 focus:border-red-500 {%- else -%} border-gray-300 focus:ring-blue-500 focus:border-blue-500 {%- endif -%} {% endmacro %} {# Inline error shown right below the field. #} {% macro field_error(error_field, field_name, form_error) %} {%- if error_field and error_field == field_name and form_error %}

{{ form_error }}
