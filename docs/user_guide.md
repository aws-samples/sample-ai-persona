## 概要

AIペルソナシステムは、インタビューデータや調査レポートからAIペルソナを生成し、ペルソナ同士の議論やインタビューを通じて、商品企画・マーケティング戦略立案のためのインサイトを生成するシステムです。

### ログインとロール

利用にはログインと、管理者が付けるロール（`admin` または `member`）が必要です。ロールがまだ付いていない場合は、ログイン後に「利用権限がまだありません」の画面が表示され、ログアウトだけができます。管理者にロールを付けてもらったら、ログアウトしてログインし直してください。

### ロールごとにできること

| | member | admin |
|---|---|---|
| ペルソナ・議論・インタビュー・アンケートを作る | ○ | ○ |
| 自分が作ったものの編集・削除・共有 | ○（共有先は自分が所属するグループだけ） | ○ |
| 共有されたものの閲覧・利用 | ○ | ○ |
| 他の人が作ったものすべての閲覧・編集・削除・共有（「すべて」タブ） | × | ○ |
| ナレッジベース・データセット・カスタムペルソナデータの利用 | 自分のグループが利用範囲に入っているものだけ | すべて |
| システム設定（データセット・ナレッジベース・データ分析エージェント・利用範囲） | × | ○ |
| ペルソナデータの準備（Nemotron のダウンロード、カスタムデータの登録・削除） | × | ○ |

**グループ** は、共有と利用範囲の単位です。どのグループに所属するかは管理者が決めます。所属するグループは、いくつあってもかまいません。管理者の手順は [利用者・ロール・グループの管理](user_management.md) を参照してください。

### 共有と権限

ペルソナ・議論とインタビュー・アンケートのテンプレートと結果は、作った人（所有者）のものです。所有者は、自分のグループに共有できます。

**一覧のタブ:** どの一覧も 3 つのタブに分かれます。検索は選んでいるタブの中で行います。

| タブ | 表示されるもの |
|---|---|
| 自分のもの | 自分が作ったもの |
| 共有されたもの | 所属するグループに共有されたもの（所有者と共有元のグループが出ます） |
| すべて（admin だけ） | すべて |

**できること:**

| 操作 | 所有者 | 共有された人 | admin |
|---|---|---|---|
| 閲覧・エクスポート・議論やアンケートでの利用 | ○ | ○ | ○ |
| 編集・削除・共有先の変更 | ○ | × | ○ |

**共有のしかた:**

1. 一覧か詳細画面の「共有」を押します
2. 共有するグループを選び、「保存」を押します（member が選べるのは、自分が所属するグループだけです）

複数をまとめて共有するときは、「自分のもの」のタブで行を選び、「共有先を設定」を押します。共有を外すと、そのグループの人はすぐに見られなくなります。所属するグループがない member は共有できません。

## 1. ペルソナ生成

「インタビュー」メニューから「ペルソナ生成」を選択すると、4ステップのペルソナ生成画面が表示されます。さまざまなデータソースから柔軟にペルソナを生成できます。

### 手順

1. **データソースの選択**: ペルソナ生成に使用するデータの種類を選択
   - インタビュー / 市場調査レポート / レビューデータ / 購買データ / その他 / データ分析エージェント連携
2. **データファイルのアップロード**: ペルソナ生成の元となるデータファイルを選択（複数可、ドラッグ＆ドロップ対応）
   - 対応形式: `.txt`, `.md`, `.pdf`, `.docx`, `.doc`, `.csv`
   - 最大: 10MB/ファイル、抽出テキスト合計20万文字まで
   - ファイルは複数回に分けて追加でき、一覧から個別に削除可能
   - 「データ分析エージェント連携」選択時はファイルアップロード不要（代わりにターゲット指定を入力）
3. **ペルソナ作成の指示（任意）**: 作成したいペルソナの特徴や条件を自然言語で指定
   - 例: 「30代女性で製品に不満を持つペルソナを作って」「ヘビーユーザーとライトユーザーの2タイプを作成して」
   - 「データ分析エージェント連携」選択時は「ペルソナのターゲット指定」として、どんな顧客層のペルソナを作りたいか条件や着目したい観点を入力
4. **生成設定**: 生成するペルソナ数を指定（1〜10個、推奨: 3〜5個）し、「ペルソナを生成」をクリック
   - 「データ分析エージェント連携」で「行動データ自動紐付け」をONにすると、生成数は1に制限され、特定ユーザーを深掘り分析してペルソナ化します。対象ユーザーの行動データ（購買履歴、Webログ等）もCSVとして自動取得され、保存時にデータセットとして紐付けられます

> **💡 生成される属性:** 名前・年齢・職業・背景・価値観・課題・目標に加え、性別・居住国・居住都市が自動生成されます。居住国はデータに応じて全世界に対応します（日本以外の国も生成可能）。タグはフィルタ用に編集画面で手動付与します。

> **💡 データ種別ごとの活用例:**
> - **インタビュー**: 顧客インタビューの書き起こしテキスト
> - **市場調査レポート**: 市場調査レポート、顧客分析資料、セグメンテーション分析資料
> - **レビューデータ**: ECサイトの商品レビュー、口コミデータ
> - **購買データ**: 購買履歴CSV、トランザクションデータ
> - **その他**: 上記に当てはまらないデータ
> - **データ分析エージェント連携**: DWHに蓄積された業務データ（売上・注文・顧客・商品等）をデータ分析エージェントが自動分析してペルソナを生成。別途データ分析エージェント連携の設定が必要です（[データ分析エージェント連携ガイド](data_agent_integration.md)を参照）

### CSVファイルアップロード時の挙動

`.csv`ファイルをデータソースとしてアップロードした場合、他の形式（PDF/Word/テキスト等）とは異なる処理になります。

- 通常ファイルは全文をテキスト抽出してAIに渡しますが、CSVは先頭20行のみをプレビューとして渡し、残りの全データはAIが構造化分析ツール（`analyze_dataset`）で必要に応じて集計・参照します（AIはSQLを書きません。集計条件を構造化引数で指定します）
- AIに渡るのは**カラム名・推定データ型**とプレビュー20行だけで、一時ファイルのパスやファイル名は渡りません
- そのため、生成されたペルソナが21行目以降のデータ（プレビュー範囲外）の傾向を反映しているかは、「生成ログ・評価」で実行された分析（tool_call/tool_result）を確認することで検証できます（[2. ペルソナ管理](#2-ペルソナ管理)参照）

### ペルソナ生成用CSVの制約と精度向上のポイント

ペルソナ生成でCSVをアップロードする場合の制約・留意点です（データセット連携で登録するCSVは[7.3 データセット連携用CSVの制約と精度向上のポイント](#73-データセット連携用csvの制約と精度向上のポイント)を参照）。

**ファイルの制約:**
- 形式: CSV（`.csv`）、ヘッダー行あり、カンマ区切り
- 列名は**一意で空でない**こと（列名が重複・空欄のCSVは集計時に列を特定できないため、アップロード時にエラーになります。前後の空白は自動的に除去されます）
- 文字コード: UTF-8推奨（Shift_JIS / EUC-JP も自動判別・変換します）
- サイズ: 最大10MB

**精度向上のポイント:**
1. **カラム名を意味の分かる名前にする（最重要）** — AIに届くのは「カラム名・推定データ型・先頭20行」です。`col1` / `amt` / `c` ではなく `purchase_amount` / `category` / `purchased_at` のように内容が伝わる名前にしてください。CSVのヘッダー行がそのまま採用されます
2. **数値列は数値のまま** — 金額などに `¥1,000` や `1,000`（カンマ・通貨記号）が混ざると `sum`/`avg` などの集計が崩れます。素の数字（`1000`）にしてください
3. **日付は `YYYY-MM-DD` 形式** — 期間の絞り込みや並び替えが安定します
4. **代表的な行を先頭に** — 初期分析はプレビュー20行に基づくため、先頭20行が偏っていると分析も偏る場合があります
5. **データの補足は「データ説明」欄・カスタム指示で伝える** — ペルソナ生成画面のデータ説明やカスタム指示に、データの意味・粒度・期間を書くと分析の方向づけが安定します

> ⚠️ **留意点:**
> - ペルソナ生成CSVでは列ごとの説明文は付けられません（型は自動推定）。意味は**カラム名**に込めてください
> - 機密データ・個人情報の取り扱いには十分注意してください

### 高度な生成（ベータ）

大きな表（CSV / TSV）を全件分析し、データの中のまとまり（セグメント）ごとにペルソナを作る試験的な機能です。各ペルソナには、そのセグメントが全体に占める割合（構成比）と、数字の根拠が付きます。インタビューの記録などの文書（PDF・Word・テキスト）からも作れ、文書の根拠は元の文章の引用付きで表示されます。結果の形や仕様は予告なく変わることがあります。

ペルソナ生成画面の上にある「**通常の生成**」「**高度な生成** ベータ」のタブで切り替えます。タブが表示されない場合は、この機能を使える設定になっていません（下記「利用範囲」を参照）。

**手順:**

1. **データファイルのアップロード**: CSV / TSV ファイルを点線の枠にドラッグ＆ドロップするか、枠をクリックして選択
   - 1ファイル最大1GB、合わせて10ファイルまで。Excel のファイルは CSV で保存し直してください
   - 大きなファイルは分割して送られ、「アップロード中 〇%」で進み具合が表示されます。送り終わるまで「取消」で中止できます
   - 送り終わると「検査中」になり、自動で中身を確かめます。使えるファイルは「**準備OK**」となり、列数・おおよその行数・文字コードが表示されます。使えないファイルは「エラー」と、理由と直し方（例: 「1 行目に空の列名があります。列名を入れて保存し直してください」「UTF-8 で保存し直してください」）が表示されます。エラーのファイルは10ファイルの数に入りません。そのファイルだけを削除して、直したファイルを上げ直せます
   - 検査が長く止まったときは、15分で表示の更新を止めて「**確定し直す**」を出します。押すと検査をやり直します
   - 同じ名前のファイルを上げると、2つ目から「sales.csv (2)」のように番号が付きます。別のタブで同じアップロードを確定しても、検査は1回だけで、どちらのタブにも同じ結果が出ます
   - 「**プレビュー**」で、列名と推定した型、先頭の数行を確認できます（行数は先頭の行から見積もった値で、分析の前準備で確定します）
   - 「使う」の欄で、今回の生成に使うファイルを選びます。表は3つまで（表の合計は1GBまで）、文書は文書だけでも、表と一緒にでも選べます（合わせて10ファイルまで）。表を4つ以上選ぶと「表は 3 つまで選べます」と出て、「ペルソナを生成」を押せません（下記「表を複数選んだとき」）
   - **前に上げたファイルの使い回し:** 上げたファイルは「上げたファイル」の一覧に残ります。ページを開き直しても、上げ直さずに指示を変えて何度でも生成に使えます
   - **消える予定の日:** ファイルは、最後に生成に使ってから7日（一度も使っていなければ上げてから7日）で自動で消えます。消える予定の日は一覧に表示され、生成に使うたびに7日後へ延びます
   - **ファイルの削除:** 一覧の「〇〇 を削除」から、確認のうえいつでも消せます。上げたファイルと検査の結果がすぐに消え、元に戻せません。生成に使っている途中のファイルは「生成中のため削除できません」と表示され、消せません（生成が終わってから消してください）。うまく消せなかったときは「削除できませんでした」と表示されるので、もう一度削除してください
   - 上げたファイルは、上げた本人だけが見られます。ほかの人の一覧には出ず、生成にも使えません
2. **ペルソナ作成の指示**（任意）: どんな観点でペルソナを作りたいかを書きます（空欄なら、データから切り口を決めます）
   - 「**分析の計画を確認してから実行する**」（既定はオフ）をオンにすると、分析を始める前に計画を確かめられます（下記「計画の確認」）
   - 「**AI による詳細分析**」は、管理者が許しているときだけ表示され、最初からチェックが入っています（下記「AI による詳細分析」）。外すと、その生成では決まった分析の機能だけを使います
3. **生成設定**: 「生成数」（1〜10）を選び、「**ペルソナを生成**」をクリック
   - 検査中・アップロード中のファイルを選んで始めると、「検査が終わっていないファイルがあります」と案内されます。「準備OK」になってから始めてください
   - 実行中の生成があるときは始められません。「実行中の生成があります。進み具合を表示しました」と出て、その生成の進み具合が表示されます。ボタンを2回押したり、別のタブから始めたりしても、生成は1つだけです
4. **進行状況**: 段階の数から出す進行状況のバー（「3 / 5 段階」）と、「前準備 → 計画 → 実行 → 合成 → 検証」の段階と、各段階の記録が順に表示されます。右上に経過時間が表示されます。ページを離れても生成は続き、生成中に画面を開き直すと続きから表示されます。同時に進められる生成は1人1件です
   - **中止:** 進み具合の右上の「**中止**」で、終わる前ならいつでも止められます。押すと「中止しています」になり、数秒で「**中止しました**」と表示されます（AI が考えている途中なら、その応答が返ってから止まるため、少し時間がかかることがあります）。途中の結果は残りません。指示とファイルの選択はそのままなので、同じファイルですぐに始め直せます
5. **結果**: 分析の要約（使った行数・除外した行数・手法。履歴を人ごとに集計したときは、層に分けた母数（人数）も）と、セグメントごとの構成比と特徴の表が表示されます。各ペルソナには「全体の 〇%」のバッジが付きます（読み方は下記「結果の見方」）
   - 「**分析の詳細**」ボタンで、分析の計画と理由、解釈した目的、使ったファイル、実際に行った分析の流れ、実行したコードを確認できます
   - 保存したいペルソナにチェックを入れ、「**選んだペルソナを保存**」をクリック
   - 検証で確かめられなかったセグメントは「検証で外したため出しません」と表示され、構成比は出ません
   - 作ったペルソナに足りないところ（価値観や根拠が空、同じセグメントを複数のペルソナが代表している、など）があるときは、進み具合に「ペルソナに足りないところがあったため、書き直します」と出て、1 回だけ書き直します。それでも足りないときは、結果を残さずに「検証に失敗しました」で止まります

**結果の見方:**

- **セグメントの表:** 各セグメントには、構成比のバーと、特徴の表（「項目 / この層 / 全体 / 比べると」）が出ます。「この層」は、そのセグメントの平均か割合、「全体」は全員の値、「比べると」は ▲ 高い / ▼ 低い です
  - 平均の項目は数値（桁区切り付き）、割合の項目は「プラン=ゴールド　その人の割合　48%」のように、その値をもつ人の割合で表示されます
  - 「最後の購入からの日数」「購入回数」「購入金額の合計」のように、AI のプログラムが人ごとに計算した指標には、項目名の下に「**AI の計算**」と出ます。値の計算は AI のプログラムのもので、平均はシステムが数えています
- **特徴の選び方:** 特徴はすべて、AI の文章ではなく、システムが全行から数え直した値です。全体との差が小さい項目（平均は標準偏差の 0.2 倍未満、割合はそれに相当する差）は、そのセグメントの特徴ではないので出しません。差の大きい順に、多くて 6 つ並びます。差の小さいセグメントでは、表が出ないこともあります
- **「どの層にも入らなかった人が N 人」:** どのセグメントにも入らなかった人数と割合です（表が 1 つのときだけ出ます。セグメントどうしが重なる場合や、検証で外したセグメントがあるときは出しません）
- **「層は N 個しか作れませんでした」:** 依頼したペルソナの数より、作れたセグメントが少なかったときの案内です。同じセグメントを代表するペルソナがあります
- **「人でなく行の数です」:** 注文や履歴のように、1 人に複数行ある表だけを使ったときの案内です。人数や割合は、人ではなく行（注文など）の数です。1 人 1 行の表と一緒に選んだときは、この案内は出ません
- **ペルソナのカード:** 名前・職業・居住地・家族・エピソード・口調は、データにない部分を AI が想像して補ったものです。背景・価値観・課題・目標は、「**根拠**」を開くと見える「**データに基づく点**」（セグメントの特徴の表）から、AI が読み解いたものです。その下の「分析の根拠」には、根拠の文と、システムが数え直した数（対象の行数つき）が並びます。特徴が付かなかったセグメントでは、背景なども「層の情報から読み解いたもので、数値の裏づけは示せていません」と注記されます

**計画の確認:**

- 「分析の計画を確認してから実行する」をオンにして始めると、計画ができたところで止まり、段階に「計画の確認待ち」と「**分析の計画**」のカードが表示されます。カードには、解釈した目的、答える問い、手法と選んだ理由、使う量の上限が出ます（目安と違う手法を選んだときは、その理由も出ます）
- カードには「**データの解釈**」も出ます。選んだ CSV をシステムがどう解釈したか（「1 人が 1 行のデータのみ」か「1 人に複数行のデータが存在」か、人を特定する列、特徴に含めない列）です。誤りがあれば、カードの上で訂正できます。訂正した解釈でペルソナを作ります。1 人に複数行の表は、人数や割合が「人でなく行の数」になります。ID・コード・郵便番号・電話番号・メールアドレス・氏名のような列は、特徴の表に出ません。解釈は「計画を承認」と「指示を修正して再計画」のどちらでも送られます。「計画の確認」をオンにしないときは、システムの解釈のまま進みます
- 「**計画を承認**」を押すと分析に進みます。「**指示を修正して再計画**」は、カードの入力欄（今の指示が入っています）を直して押すと、その指示で計画を作り直します（回数の制限はありません）。「中止」でやめることもできます
- カードは **15分** 待ちます。15分のうちに選ばないと生成は止まり、「計画の確認を 15 分待ちましたが、承認がなかったため止めました」と表示されます。計画し直しを重ねた場合も、待てる時間は合わせて60分までです
- 待っている間は経過時間が止まり、生成の60分の制限にも数えません

**AI による詳細分析:**

- 決まった分析の機能（絞り込み・集計・クラスタリング）で足りないとき、AI が分析用のプログラムを作り、その生成のためにほかから切り離した分析の環境で動かして、表を結合したり、群どうしの差を検定したり、購買の新しさ・頻度・金額で顧客を分けたり（RFM）します
- 人数と割合は、AI のプログラムが出した数字ではなく、テスト済みの関数がデータから数え直した値だけを使います
- うまく動かないときは AI が直して試します。合わせて5回失敗すると、進み具合に「AI による詳細分析をやめて、事前定義された関数で続けます」と出て、決まった機能だけで生成を最後まで続けます。失敗したプログラムやエラーの文は、結果にも分析の詳細にも出ません
- 「分析の詳細」には、成功したプログラムが「**AI による詳細分析**」として、あらかじめ用意した処理が「**事前定義された関数**」として並びます
- 分析の途中で、分析の機能や前準備のデータが書き換えられたと分かったとき、または AI のプログラムが止めたはずの処理を残していたときは、結果を残さずに「分析に失敗しました」で止まります
- ⚠️ ベータの注意: AI が作ったプログラムは、その生成を始めた本人のデータ（選んだファイル）の中だけで動き、生成が終わると環境ごと消えます。動かしたプログラムは分析の詳細に残ります。結果の数字は検証していますが、AI の分析の進め方は試験的なものです。分析の環境からは AWS の一部のサービスに接続できるため、信頼できるデータにだけ使ってください（外部の人が書いた指示が入っているかもしれないファイルには使わないでください）
- 管理者が設定画面で許したときだけ使えます（[8.6 高度な生成（ベータ）の設定](#86-高度な生成ベータの設定)）。許可を変えても、すでに始まった生成はそのまま動きます

**表を複数選んだとき:**

- 選んだ順に「source_1」「source_2」「source_3」と呼ばれ、表ごとに前準備と要約をします（前準備の20分は表と文書を合わせて数えます）。手法の目安は、1行が1人の表（なければ最初の表）で決めます
- **共通の ID 列があるとき:** AI による詳細分析を使う生成では、1行が1人の表を軸にして、ほかの表と同じ名前の ID の列（例: `customer_id`）の値の半分以上が重なれば、その列で結合します。購買履歴のように1人に複数行がある表は、人ごとに集計（件数・合計・最後の日付など）してから付け、一致しなかった人も「一致なし」として残します。分析の詳細に「結合した列」と一致の割合が表示されます
- **共通の列がないとき、または AI による詳細分析を使わないとき:** 結合せず、表ごとに別のデータとして分析します

**文書（PDF・Word・テキスト）から作るとき:**

- **使える形式:** PDF（.pdf）、Word（.docx）、テキスト（.txt・.md）。1ファイル最大100MB。古い Word（.doc）は .docx で、Excel は CSV で保存し直してください
- **受け取り時の検査:** 中身が拡張子と合わないファイルは「エラー」になります。**パスワード付きのファイル**は読めないため、パスワードを外してから上げ直してください（古い Word の形式も同じ表示になります）。テキストの文字コード（UTF-8・Shift_JIS など）は自動で判定します
- **文字数の見込み:** 文書の行には「PDF / 約 〇 万字の見込み」が表示され、選んだ文書の合計の見込みも出ます。見込みは目安で、ページ数と文字数は生成の前準備で確定します
- **文字のないページ:** 画像だけのページなど文字のないページは除いて続けます（進み具合に「〇 ページは文字がないため除外しました」と出ます）。文字を読み取る処理（OCR）はしないため、**すべてのページに文字がない文書**では生成が止まり、そのファイル名が案内されます。そのファイルを外して生成し直してください
- **上限と進め方:** 選んだ文書の文字数の合計が200万字を超えると、前準備のあとに止まります（確定した文字数と上限が表示されます）。合計が20万字以内なら文書の全文を使い、それを超えると文書を分けて根拠を取り出してから作ります（進み具合に「根拠の抽出 n / M」が出ます）
- **引用の照合:** 根拠の引用は、元の文書にある文章かを自動で照合し、見つからないものは結果に出しません（除いた数は結果に表示されます）。表と一緒に使うと、文書の根拠は条件が合うセグメントに対応づけられ、どのセグメントにも合わないものは「**全体に対する根拠**」として表示されます
- **結果:** 「使った文書」にファイル名・ページ数・文字数が、各ペルソナの「根拠」に引用・位置（ページ・見出し）・発言者の属性が表示されます

**うまく進まないとき:**

- **壊れた行が多いとき:** 列の数が合わない行や、文字コードを読めない行（除外した行）が全体の1%を超えると、生成は止まります（1%以下なら除外して続け、結果に除外した行数を出します）。画面に「3、21 行目などに問題があります」のように行番号の例（最大5件）が出るので、元のファイルのその行を直して上げ直してください。行の中身は画面にもログにも出ません
- **データの行数が少ないとき:** 読めた行数が「ペルソナの生成数 × 10」に満たないと、分析に進まず止まります（例: 5人なら50行）。指示で対象を絞る、人数を減らす、行数の多いファイルを使う、のどれかを試してください
- **表が大きすぎるとき:** 前準備でメモリが足りなくなると、「おおよそ ○ 行・○ 列」の目安つきで止まります。ファイルを小さくして（行や列を減らして）試してください
- **大きな表の進み具合:** 1GB ほどの表では前準備に時間がかかります。読み込んだ行数が増えない間も、60秒ごとに「前準備を続けています（○ 分経過）」と表示されるので、止まったわけではありません
- **処理が途中で止まったとき:** 生成を動かしていたサーバーが落ちるなどして、5分以上進み具合が届かない生成は「生成の処理が途中で止まりました。もう一度始めてください」と表示されて終わります（画面を開き直したときや、次の生成を始めたときに判定します）。使っていたファイルはすぐに使えるようになるので、そのまま始め直してください
- **失敗の表示:** 失敗したときは、理由と直し方が表示されます（内部のエラーの文は出ません）。分析の処理（Code Interpreter）に届かないときは「分析の処理に一時的に失敗しました」と出ますが、通常の生成やほかの画面はそのまま使えます。失敗のあとも指示とファイルの選択は残るので、すぐに始め直せます

> ⚠️ **保存していない結果は、生成の完了から24時間で見られなくなります。** 残したいペルソナは期限内に保存してください（期限は「D. 結果」の上に表示されます）。

**保存したペルソナ:** ペルソナの詳細画面に「**高度な生成（ベータ）で作成**」のバッジと分析の要約（手法・セグメント・構成比）が表示され、「分析の詳細」ボタンで生成時の記録を確認できます。元のファイルを消したあとも記録は残り、ファイル名の横に「元のファイルは消えています」と表示されます（この機能の初期に作ったペルソナでは「元のファイルの記録はありません」と表示されます）。

**使える人:** 管理者（`settings:manage` の権限を持つ `role:admin`）はいつでも使えます。ほかの人は、管理者が設定画面で「全員」か部署を選んで公開したときに使えます（[8.6 高度な生成（ベータ）の設定](#86-高度な生成ベータの設定)）。何も設定していないときは管理者だけです。閉域構成では使えません（[閉域構成ガイドの「閉域で使えない機能」](closed_network.md#閉域で使えない機能)を参照）。

## 2. ペルソナ管理

「インタビュー」メニューから「ペルソナ管理」を選択すると、保存済みペルソナの一覧が表示されます。

### 基本操作

- **確認**: 各ペルソナの詳細情報を表示
- **生成ログ・評価**: 「生成ログ・評価」ボタンでペルソナ生成時のAI分析過程を確認（生成ログがあるペルソナのみ表示）
- **編集**: 「編集」ボタンでペルソナ情報を修正（名前・年齢・職業に加え、性別・居住国・居住都市・タグも編集可能）
- **削除**: 「削除」ボタンで削除（確認ダイアログあり）。紐付け・長期記憶・アイコン画像なども一緒に削除され、元に戻せません
- **エクスポート**: 詳細画面の「エクスポート」で、ペルソナを Markdown ファイルとしてダウンロード
- **属性フィルタ**: 一覧上部のフィルタで、性別・居住国・タグによる絞り込みが可能
- **共有**: グループに共有できます（[共有と権限](#共有と権限)）。共有すると、生成過程も共有先に見えます

生成したペルソナは、8 時間以内に保存してください。それを過ぎると保存できなくなります（生成し直してください）。

> **💡 共有したペルソナの記憶:** 所有者との会話で蓄積された記憶は、共有先の人との会話でも使われます。共有先の人との会話は記憶に書き込まれず、共有先の人は記憶の一覧を見られません。

### アイコン画像の変更

ペルソナのアイコンは、ペルソナIDから自動生成されたアバターが表示されます。ペルソナ詳細画面でアイコン下の「画像を変更」から画像をアップロードすると差し替えられます。

- 対応形式: PNG / JPEG / WebP（5MB以下。画素数は JPEG が5,000万画素以下、PNG・WebP が1,600万画素以下）
- アップロードした画像は中央を正方形に切り抜き、256×256ピクセルに縮小して保存されます。撮影位置などの画像メタデータは保存されません
- 変更したアイコンは一覧・議論・インタビュー画面にも反映されます
- 「自動アバターに戻す」で、アップロードした画像を削除して自動生成アバターに戻せます
- 画像の保存先（S3バケット）が設定されていない環境では、この機能は表示されません

### 生成ログ・評価の確認

ペルソナ詳細画面の「生成ログ・評価」ボタンをクリックすると、ペルソナ生成時のAI分析・評価過程をモーダルで確認できます。

**表示内容:**

- **ペルソナ生成インプットデータ**: データソース種別、入力ファイル名、指示プロンプト、生成数、生成日時
- **AI 分析・評価過程**: AIがデータを分析した思考過程、実行したクエリ（tool_call）、分析結果（tool_result、折りたたみ表示）

> **💡 ポイント**: 生成ログを確認することで、AIがどのようなデータ分析に基づいてペルソナを構築したかの根拠を追跡できます。データ充足度の評価やペルソナの信頼性判断に活用してください。

### 長期記憶・知識の管理

ペルソナ詳細画面の「長期記憶」セクションで管理します（所有者と admin だけ）。2つのタブがあります。

| タブ | 内容 | 手動追加 |
|------|------|----------|
| 議論の記憶 | 議論で保存された要約記憶 | ❌ |
| 知識・事実 | ペルソナが持つ事実情報や知識 | ✅ |

各記憶には保存日時と内容が表示されます。重要度（重要/通常/低）とセッションIDは、記憶にその情報がある場合のみ表示されます（手動追加した知識・事実には表示されません）。トピック付きの知識・事実は、トピック名がラベルとして表示されます。

**知識の追加方法（知識・事実タブのみ）:**

- 「知識・事実情報を追加」ボタンからトピック名と内容を入力して追加
- ファイルからの追加にも対応（対応形式: PDF, Word, PowerPoint, Excel, テキスト / 10MB以下）
  - 自動的にMarkdown形式に変換されてプレビューに出ます。確定した内容だけが知識として保存されます
  - 変換後の内容は10,000文字以内である必要があります（超過時はエラーとなり、ファイルを分割するか、より小さいファイルを使用してください）

**削除**（いずれも確認ダイアログあり）:

- 個別削除: 各記憶にマウスを重ねると右側に表示される削除ボタンから削除
- 一括削除: タブ下部の「全ての記憶を削除」（議論の記憶タブ）／「全ての知識・事実を削除」（知識・事実タブ）で、表示中のタブの記憶をすべて削除

### ナレッジベースの紐付け（オプション）

ペルソナ詳細画面の「ナレッジベース連携」セクションで、Amazon Bedrock Knowledge Baseをペルソナに紐付けできます。紐付けたナレッジベースの情報は議論・インタビュー時にペルソナが参照します。ナレッジベースの登録・管理は「システム設定」ページから行います。

1. 登録済みナレッジベースの一覧から、紐付けたいものの「紐付ける」をクリック
2. 表示されるダイアログでメタデータフィルタを設定（オプション）。「+ 追加」でキー名と値の組を追加すると、ナレッジベース検索時にそのメタデータを持つドキュメントだけが検索対象になります。未設定の場合は全ドキュメントが検索対象です
3. ダイアログの「紐付ける」で確定

紐付け後は「紐付け済み」と表示され、設定したフィルタも併記されます。「解除」で紐付けを解除できます（確認ダイアログあり）。

紐付けの追加・解除ができるのは所有者と admin だけです。紐付けられるのは、自分が使えるナレッジベース・データセットだけです（[8.5 組織資産の利用範囲](#85-組織資産の利用範囲)）。自分が使えないものには「〔利用権限なし〕」と表示されます。ペルソナ生成時に一緒に保存した行動データ（「〔このペルソナ専用〕」）は、紐付けを解除すると削除されます。

## 3. 議論・インタビューの実行

「インタビュー」メニューから「議論設定」を選択して開始します。

### 3.1 共通設定

1. **モード選択**: 簡易議論 / しっかり議論 / インタビュー から選択
2. **ペルソナ選択**: 議論モードは最低2体、インタビューモードは1体以上
   - 年齢レンジ・性別・居住国・職業・タグでペルソナを絞り込み可能
   - 各カードの「詳細」リンクから、別タブでペルソナ詳細を確認できます
3. **ドキュメント添付（オプション）**: 画像（PNG/JPEG）やPDFをアップロード
   - 画像は1枚5MB、PDFは1ファイル10MB、合計32MB以内
   - ペルソナがドキュメントを参照しながら議論・対話します
4. **インサイトカテゴリーのカスタマイズ（議論モードのみ・オプション）**:
   - デフォルト5カテゴリー（顧客ニーズ、市場機会、商品開発、マーケティング、その他）
   - 名前（最大50文字）と説明（最大500文字）を編集可能
   - 最大10個まで追加、最低1個は必要
5. **長期記憶の有効化（しっかり議論・インタビューのみ・オプション）**:
   - 「長期記憶・知識を有効にする」チェックボックスをオン
   - ペルソナが過去の議論を記憶・活用できるようになります
   - AgentCore Memoryの事前設定が必要
6. **ナレッジベース連携の有効化（しっかり議論・インタビューのみ・オプション）**:
   - 「ナレッジベース連携を有効にする」チェックボックスをオン
   - ペルソナに紐付けられたナレッジベースから情報を検索・取得できるようになります

**共有されたペルソナと組織の資産について:**

- 自分のペルソナに加えて、共有されたペルソナ（〔共有〕と表示）も選べます。共有されたペルソナとの会話は、そのペルソナの記憶に書き込まれません
- ペルソナに紐付いたナレッジベース・データセットのうち、自分が使えないものは使われません（[8.5 組織資産の利用範囲](#85-組織資産の利用範囲)）
- 添付したドキュメントはその議論だけで使えます。別の議論で使うときは、もう一度アップロードしてください

### 3.2 簡易議論モード

全ペルソナが同時に議論テーマについて発言する高速モードです。

**特徴**: 1回のAI呼び出しで全発言を生成 / 処理時間3〜5分 / マルチモーダル対応

**使い方:**
1. 「簡易議論モード」を選択し、ペルソナとトピックを設定
2. 表示モードを選択（通常表示 or リアルタイム表示）
3. 「議論を開始」をクリック

**向いているケース**: 迅速な意見収集、基本的な意見収集

### 3.3 しっかり議論モード

各ペルソナが独立したAIエージェントとして動作し、ファシリテータが進行管理するモードです。

**特徴**: ラウンド制で順番に発言 / より自然で深い議論 / ファシリテータによる要約 / 長期記憶対応

**使い方:**
1. 「しっかり議論モード」を選択し、ペルソナを選択（2〜5体推奨）
2. ペルソナ毎に使用モデルを選択（オプション、デフォルト: Claude Haiku 5.5）
3. ファシリテータ設定:
   - **ラウンド数**: 1〜10（推奨: 3〜5）
   - **追加指示（オプション）**: 例「対立する意見を引き出してください」
   - **ファシリテータのモデル**: 使用モデルを選択（オプション、デフォルト: Claude Haiku 5.5）
4. 必要に応じて長期記憶・外部データ連携を有効化
5. 「議論を開始」をクリック（処理時間: 5〜15分）

**結果表示**: ラウンドごとにセクション分け、ペルソナ発言とファシリテータ要約が色分け表示

**向いているケース**: 深い洞察、ペルソナ間の相互作用重視、質の高い議論

### 3.4 インタビューモード

ユーザーがペルソナと直接リアルタイムでチャット形式の対話を行うモードです。

**特徴**: 1対多のインタビュー形式 / リアルタイムUI / セッション保存 / 長期記憶対応

**使い方:**
1. 「インタビューモード」を選択し、ペルソナを選択（1〜5体）
2. ペルソナ毎に使用モデルを選択（オプション、デフォルト: Claude Haiku 5.5）
3. 「インタビューを開始」をクリック → チャット画面に遷移
4. テキスト入力で質問を送信（送信ボタンまたは ⌘/Ctrl+Enter キーで送信。Enter は改行）
5. 各ペルソナが個別に応答（ペルソナごとに色分け表示）

**セッション管理:**
- 「保存」ボタンでセッション名を付けて保存。保存したあとも続けて質問でき、もう一度「保存」を押すと続きが追記されます
- 保存済みインタビューは議論履歴ページで確認可能
- ブラウザを閉じても、保存前であればセッションは続きます。ただし、8 時間操作しないと続けられなくなるため、必要なものは先に保存してください

**会話を続けられないとき:** 参加しているペルソナが削除された・共有が外れたなどで続けられないときは、「このインタビューは続けられません」（議論は「この議論は続けられません」）と表示されます。送れなかった発言は入力欄に戻ります。

**コツ:**
- 具体的で明確な質問をすると、より詳しい回答が得られます
- 一度に複数の質問をするより、一つずつ深掘りする方が有効です
- ペルソナの背景や価値観に関連する質問が効果的です

## 4. 議論結果の確認と保存

議論詳細画面では「議論内容」「インサイト」「レポート」の3つのタブで結果を確認できます。

1. **議論内容タブ**: 各ペルソナの発言が時系列・色分けで表示
2. **インサイトタブ**: カテゴリ別に整理され、信頼度スコア（0〜100%）付きで表示
   - 「カテゴリーを変更して再生成」でカテゴリーを変更可能（議論内容は変更されません）
3. **レポートタブ**: 議論結果からカスタマイズされたレポートを生成

**参加者の表示:** 今は見られないペルソナには〔参照権限なし〕、削除されたペルソナには〔削除済み〕と出ます。発言の内容はそのまま読めます。

**エクスポート:** 詳細画面の「エクスポート」で、議論を Markdown ファイルとしてダウンロードできます。

**共有された議論:** 閲覧・エクスポート・レポートの閲覧ができます。インサイトの再生成とレポートの保存は、所有者と admin だけができます。

### レポート生成

議論結果から施策やアクションに繋がるレポートを生成できます。

1. **テンプレート選択**: 3種類から選択（データ分析エージェント連携が有効な場合は4種類）
   - **サマリレポート**: エグゼクティブサマリ、主要な発見、示唆、推奨アクション（優先度・難易度付き）
   - **レビューコメント**: 該当箇所、指摘内容、重要度、推奨アクションを表形式で整理
   - **カスタム**: 自由にプロンプトを入力して出力形式を指定
   - **データドリブン分析（データ分析エージェント連携）**: 定性インサイトをDWHの実データで裏付け・反証し、意思決定・施策実行に繋がるレポートを生成。別途データ分析エージェント連携の設定が必要です（[データ分析エージェント連携ガイド](data_agent_integration.md)を参照）
2. **生成**: 「レポートを生成」ボタンでSSEストリーミング生成（リアルタイムでMarkdown表示）
   - データドリブン分析ではCSVエクスポートリンクが自動生成される場合があります（有効期限: 約1時間）
3. **プレビュー確認**: 生成完了後、プレビューを確認
4. **保存**: 「保存する」ボタンでDBに保存（1議論あたり最大3件）
5. **フォローアップ分析**（データドリブン分析のみ）: 保存済みレポートから「追加分析を実行」で深掘り分析を指示可能。結果は「レポートを更新」で既存レポートに追記保存できます
6. **エクスポート**: 保存済みレポートをMarkdown (.md) またはテキスト (.txt) でダウンロード
7. **削除**: 保存済みレポートは個別に削除可能（確認ダイアログあり）

> **💡 ポイント**: レポートにはペルソナのプロフィール（価値観・課題・目標）が分析コンテキストとして含まれるため、「なぜその発言が出たか」の背景分析が可能です。

### インサイトの信頼度スコア

| 信頼度 | 意味 |
|--------|------|
| 90〜100% | 複数ペルソナが明確に言及、具体的な根拠あり |
| 70〜80% | 議論の中で明確に表現、十分な根拠あり |
| 50〜60% | 議論から推測可能だが、間接的な根拠 |
| 30〜40% | 文脈から読み取れるが、推測の要素が強い |
| 10〜20% | 一般的な推測に基づく |

> **💡 活用のポイント**: 70%以上のインサイトを優先的に検討し、低い信頼度のものは追加検証を行いましょう。

## 6. マスアンケート機能

数百〜数千のAIペルソナに対して大規模アンケート調査を実行し、VoC（Voice of Customer）を効率的に収集する機能です。

### 6.1 ペルソナデータの準備

「アンケート」メニューから「ペルソナデータ設定」を選択します。

ペルソナデータの準備（Nemotron のダウンロード、カスタムデータの登録・削除）ができるのは **admin だけ** です。member には、自分のグループで使えるカスタムデータの一覧だけが表示されます。追加や削除は管理者に依頼してください。

**オープンデータセット（Nemotron）:**
- Hugging FaceのNemotron-Personas-Japanデータセットをダウンロード（admin）

**カスタムペルソナデータの追加（オプション、admin）:**

「CSVアップロード」と「データ分析エージェント連携」の2つの方法から選択できます。どちらも、確定するときに **データセット名**（ほかと重ならない名前）と **利用できるグループ** を決めます。グループを選ばないと admin だけが使えます。グループはあとから一覧の「利用範囲」で変えられます（[8.5 組織資産の利用範囲](#85-組織資産の利用範囲)）。

> **v1.0.0 より前に登録したカスタムデータについて:** v1.0.0 からカスタムデータは ID で管理します。以前に登録したファイルは一覧に出ないため、必要なものは登録し直してください。

**方法1: CSVアップロード**
1. CSV形式のファイルをアップロード（最大500MB）
2. カラムマッピング画面でCSVカラムをシステム標準項目に対応付け
   - サンプルデータ（先頭3行）がプレビュー表示
   - カラム名が標準名と一致する場合は自動マッピング
   - 「ペルソナ概要」は必須項目
3. **その他項目の追加**: 標準項目以外のカラム（例: 会員ランク、来店頻度）もプロンプトに含められます
   - 「+ 項目を追加」でCSVカラム・ラベル名・補足情報を設定
4. 「プロンプトをプレビュー」で生成されるプロンプトを事前確認可能
5. データセット名と利用できるグループを決めて確定すると、Parquet形式に変換されてS3に保存

**方法2: データ分析エージェント連携**

DWH（データウェアハウス）から自然言語で顧客セグメントを抽出してペルソナデータとして使用します。別途データ分析エージェント連携の設定が必要です（[データ分析エージェント連携ガイド](data_agent_integration.md)を参照）。

1. 「データ分析エージェント連携」タブを選択
2. 抽出条件を自然言語で入力（例: 「東京都在住の30代女性で年間購入額50万以上」）
3. 「抽出開始」をクリック → エージェントがDWHと対話しながらセグメントを抽出（進捗がリアルタイム表示）
4. 抽出完了後、データセット名が自動生成されプレビュー画面が表示
   - データセット名は確認・編集可能
   - カラムマッピングがLLMにより自動提案（標準項目＋その他項目）
5. マッピングを確認・調整して確定 → Parquet変換されて保存
   - 件数制限: 最小10件、最大10,000件

### 6.2 アンケートテンプレートの作成

「アンケート」メニューから「テンプレート管理」を選択します。

**一覧と共有:** テンプレートの一覧も「自分のもの」「共有されたもの」「すべて（admin だけ）」のタブに分かれ、自分のテンプレートはグループに共有できます（[共有と権限](#共有と権限)）。共有されたテンプレートでも、アンケートを実行できます。テンプレートを削除しても、実行済みの結果は残ります。

**作成の手順:**

1. テンプレート名を入力
2. 質問を追加（3種類から選択）:

| 質問タイプ | 説明 |
|-----------|------|
| 選択式 | 複数の選択肢から回答（選択肢2つ以上必須） |
| 自由記述 | テキストで自由に回答 |
| スケール評価 | 1〜5の数値スケールで評価 |

3. 画像の添付（オプション、3枚まで。質問文で画像を指すため、画像ごとに違う名前を付けます）
4. 「保存」で保存

#### 💡 AIによる設問ドラフト自動生成

右上の「AIで生成」ボタンから、AIチャットでアンケート設問を自動生成できます。

1. 「AIで生成」をクリック → 右側にAIアシスタントパネルが開きます
2. 調査目的・想定ターゲット・重視したい観点などをチャットで入力（⌘/Ctrl+Enter で送信、Enter で改行）
3. 必要に応じてAIと数ターンやり取りして要件を詰める
4. 「ドラフト生成」ボタンをクリック → AIが3〜8問の設問ドラフトを自動生成し、フォームに追加されます
5. テンプレート名が未入力の場合はAIの提案が自動入力されます（入力済みの名前は上書きしません）
6. 生成された設問は既存の編集UIで自由に修正・削除・並び替えが可能です
7. 内容を確認して「保存」で保存

> **ポイント**: AI生成は「ドラフト作成の支援」です。最終的な設問内容は必ずご自身で確認・調整してください。

### 6.3 アンケートの実行

1. 「アンケート開始」メニューを選択（テンプレートの一覧の「使う」からも開けます）
2. **テンプレート選択**: 自分のテンプレートか、共有されたテンプレートから選択
3. **設定入力**: アンケート名、説明（オプション）
4. **データソース選択**: Nemotronまたはカスタムデータセット（含まれるペルソナ数が表示されます）。カスタムデータは、自分のグループで使えるものだけが選べます
5. **属性フィルタ（オプション）**: 性別、年齢、職業、出身国、居住地域、都道府県、結婚・子供の有無
   - 「対象ペルソナをプレビュー」で対象ペルソナの属性分布を事前確認可能
6. **対象ペルソナ数**: 10〜10,000（画像付きテンプレートは最大1,000）
7. 「アンケート実行」をクリック → バックグラウンドで実行（画面を閉じてもOK）

### 6.4 結果の確認

「結果表示」メニューから完了済みアンケートを選択します。結果の一覧も同じタブに分かれ、自分の結果はグループに共有できます（[共有と権限](#共有と権限)）。レポートの生成は、所有者と admin だけができます。

あとでテンプレートを編集・削除しても、過去の結果は実行したときの質問のまま変わりません。

| タブ | 内容 |
|------|------|
| 調査対象ペルソナ | 調査対象ペルソナの属性分布 |
| ダウンロード | CSV形式で結果データをダウンロード |
| 集計結果 | 選択式質問の回答分布・スケール評価の棒グラフ |
| レポート | AIによるインサイトレポート |

- **レポートの保存**: アンケートのインサイトレポートは生成完了時に自動保存されます（議論レポートのように手動で「保存する」操作は不要）
- **削除**: アンケート結果は結果一覧または詳細画面から、アンケートテンプレート（6.2）は一覧から削除可能。カスタムペルソナデータセット（6.1）の削除は admin だけです（いずれも確認ダイアログあり）

> **💡 マスアンケートのコツ:**
> - ペルソナ数は10件以上が必要。アンケートは1件ずつ順番に実行し、前のアンケートが終わるまでは「待ち」と表示されます
> - フィルタで特定セグメントに絞り込むと、より意味のあるVoCを収集可能
> - 選択式質問は集計が容易、自由記述は深い洞察が得られます

## 7. 外部データセット連携（実験的機能）

ペルソナが外部データ（購買履歴、行動ログなど）を構造化ツール `analyze_dataset` で参照し、より具体的で根拠のある発言ができるようになる機能です（利用者はSQLを書きません。ペルソナが集計条件を指定します）。

### 7.1 セットアップ

**① データセットのアップロード:**
1. システム設定ページの「データセット管理」→「データセットをアップロード」
2. CSVファイルを選択（UTF-8推奨、最大10MB）
3. データセット名・説明を入力、スキーマを確認・編集して保存
   - カラム名はCSVヘッダーから自動取得、データ型は自動推定
   - CSVの形式・精度向上のポイントは[7.3 データセット連携用CSVの制約と精度向上のポイント](#73-データセット連携用csvの制約と精度向上のポイント)を参照。特に**データセット名・説明・カラム名・カラムの型/説明**はペルソナ（AI）に提示されるため丁寧に設定してください

**② ペルソナとデータセットの紐付け:**
1. ペルソナ詳細画面の「データセット紐付け」セクションを開く
2. データセットを選択し、紐付けキー（例: `user_id = "U12345"`）を入力して保存
   - **紐付けキーは列名を実データと完全一致させ、値も実在する表記にしてください**（`user_id` と `userid` は別物。不一致だと該当データが0件になります）。この絞り込みはサーバー側で必ず適用され、ペルソナは解除・変更できません
   - 複数キーの設定も可能（例: `user_id` + `region`）
   - 「キー列で絞り込む」をOFFにすると、キー指定なし（全行対象）で紐付けも可能です。1ユーザー分のデータのみ含むデータセットに適しています

### 7.2 使用方法

1. 議論設定ページで「しっかり議論モード」または「インタビューモード」を選択
2. 「外部データセット連携を有効にする」チェックボックスをON
3. 議論/インタビューを開始

**質問例:**
- 「最近の購買履歴を教えてください」
- 「よく購入する商品カテゴリは何ですか？」
- 「過去1年間の購入金額の合計は？」

> ⚠️ **注意事項:**
> - 実験的機能です。本番環境での使用は十分なテストの後に行ってください
> - 大量データを含むデータセットはクエリに時間がかかる場合があります
> - 機密データの取り扱いには注意してください
> - 外部データセット連携を無効にしたい場合は、環境変数 `ENABLE_DATASET_ANALYSIS=false` またはCDKパラメータ `enableDatasetAnalysis: false` を設定してください（既定は有効）

### 7.3 データセット連携用CSVの制約と精度向上のポイント

連携用にデータセットを登録する場合の制約・留意点です（ペルソナ生成用CSVは[ペルソナ生成用CSVの制約と精度向上のポイント](#ペルソナ生成用csvの制約と精度向上のポイント)を参照）。

**ファイルの制約:**
- 形式: CSV（`.csv`）、ヘッダー行あり、カンマ区切り
- 列名は**一意で空でない**こと（列名が重複・空欄のCSVは集計時に列を特定できないため、アップロード時にエラーになります。前後の空白は自動的に除去されます）
- 文字コード: UTF-8推奨（Shift_JIS / EUC-JP も自動判別・変換します）
- サイズ: 最大10MB

**ペルソナ（AI）に提示される情報:**
議論／インタビューで、ペルソナには **データセット名 / 説明 / カラム名・型・説明 / 行数** が提示されます。S3パス・紐付けキーの値・SQLは提示されません（絞り込みはサーバー側で強制付与されます）。したがって、下記を丁寧に設定すると分析の精度が上がります。

**精度向上のポイント（AIに効く順）:**
1. **データセット名を具体的に** — 複数データセットを紐付けたとき、ペルソナはこの名前を手がかりに使う対象を選びます。`データ1` ではなく `2024年 購買履歴` のように内容が分かる名前に
2. **「説明」欄にデータの意味・粒度・期間・主要列の意味を書く** — 例:「1行=1回の購買。2023-01〜2024-12。amount=税込金額(円)、category=商品カテゴリ」。この説明はペルソナに提示され、集計軸や指標の選択が正確になります
3. **カラム名を意味の分かる名前にする** — CSVヘッダーがそのまま採用されます。`amt` ではなく `purchase_amount` のように
4. **カラムの型・説明を設定する** — スキーマ確認画面で各列の型を確認し（数値列が `integer`/`float` になっているか）、説明を入力してください。型・説明はペルソナに `列名 (型): 説明` の形で提示されます
5. **数値列は数値のまま／日付は `YYYY-MM-DD`** — 通貨記号・カンマ混在は集計を崩します。日付形式が揃うと期間フィルタ・並び替えが安定します

**紐付けキー（binding_keys）の注意:**
- キーの**列名をデータセットの列名と完全一致**させてください（`user_id` と `userid` は別物）。不一致だと該当データが0件になります（fail-closed）
- **値も実データに存在する表記**であること（`U12345` が実際の表記と一致すること）
- 対象データセットが**1ユーザー分だけ**なら「キー列で絞り込む」をOFFにして全行対象にできます
- この絞り込みはサーバー側で必ず適用され、**ペルソナは解除・上書きできません**

> ⚠️ **留意点:**
> - **「補足情報（notes）」欄はペルソナ（AI）には渡りません。** 運用者向けメモのための欄です。AIに効かせたい情報は「説明」欄・カラム名・カラム説明に書いてください

## 8. システム設定

管理者向けの各種連携設定を行うページです。画面上部のナビゲーションバー右側の「設定」から遷移します。

この画面を使えるのは **admin だけ** です（member には「設定」が表示されません）。

### 8.1 データ連携機能

- 登録したデータセットをペルソナに紐付けると、議論やインタビューのときに、ペルソナが自分のデータ（購買履歴や行動ログなど）を参照し、より具体的で根拠のある発言ができるようになります
- 外部SQLエンジンや追加サーバーの起動は不要です（アプリ内蔵のDuckDBで動作します）
- 全体を無効化する場合は環境変数 `ENABLE_DATASET_ANALYSIS=false`（CDKでは `enableDatasetAnalysis: false`）を設定してください
- 詳細は[7. 外部データセット連携（実験的機能）](#7-外部データセット連携実験的機能)を参照してください

### 8.2 データセット管理

「データセット管理」セクションから、外部データセット連携（7章）で使うCSVデータセットを管理します。

- **一覧表示**: アップロード済みデータセットの名前・カラム数・行数を表示
- **新規アップロード**: CSVファイルを選択（最大10MB） → スキーマプレビュー（カラム名の自動取得、データ型の自動推定）→ データセット名・説明・補足情報を入力して保存。CSV以外のファイルを選択した場合は、ブラウザのポップアップで通知されます
- **編集**: 一覧の「編集」ボタンから、データセット名・説明・補足情報・カラム（型・説明）を修正
- **削除**: 確認ダイアログあり。ペルソナへの紐付けも一緒に解除されます

### 8.3 ナレッジベース管理

「ナレッジベース管理」セクションから、Amazon Bedrock Knowledge Baseの登録・管理を行います。登録したナレッジベースは、[2. ペルソナ管理](#2-ペルソナ管理)の「ナレッジベースの紐付け」でペルソナに紐付けられます。

- **一覧表示**: 登録済みナレッジベースの名前・ID・種類を表示
- **新規作成**: Bedrock Knowledge Base ID（英数字）・種類・名前・説明（任意）を入力して登録（Knowledge Base自体の作成はAWSコンソール等で事前に行う必要があります）。種類は、作成した KB と同じもの（「Self-managed KB」または「Managed KB」）を選びます。なお、Managed KB のデータソースで ACL（文書単位のアクセス制御）を有効にしている場合、そのデータソースからは検索結果が返りません（このアプリは検索時に利用者の情報を渡さないため）。説明は、ペルソナがそのナレッジベースを検索するかどうかを判断する手がかりになるため、収録内容を具体的に書くことを推奨します
- **削除**: 確認ダイアログあり。ペルソナへの紐付けも一緒に解除されます（Bedrock の Knowledge Base 自体は削除されません）

### 8.4 データ分析エージェント連携設定

「データ分析エージェント連携」セクションから設定します。（デプロイ時に連携オプションを有効化している場合は自動で反映されます。）

1. **有効化**: 「データ分析エージェント連携を有効にする」チェックボックスをオン
2. **AgentCore Runtime ARN**: データ分析エージェントのRuntime ARNを入力
3. **リージョン**: データ分析エージェントをデプロイしたリージョンを入力（デフォルト: ap-northeast-1）
4. **保存**: 「保存」ボタンで設定を保存
5. **接続テスト**: 有効化とRuntime ARNが保存されている場合に表示される「接続テスト」ボタンで接続を確認

> 💡 データ分析エージェントの詳細なセットアップ手順は[データ分析エージェント連携ガイド](data_agent_integration.md)を参照してください。

### 8.5 組織資産の利用範囲

組織のナレッジベース（8.3）・データセット（8.2）と、アンケートのカスタムペルソナデータ（6.1）は、**利用範囲** に入っているグループの人だけが使えます。admin は利用範囲にかかわらずすべて使えます。

- **既定は admin のみ**: 登録したばかりの資産は、どのグループも使えません
- **設定のしかた**: 各一覧の「利用範囲」ボタンから、使えるグループを選んで「保存」します
- **外すとき**: 外したグループの人は、すでにペルソナに紐付けていても、次の議論・インタビュー・アンケートからその資産を使えなくなります（紐付けには「〔利用権限なし〕」と表示されます）

### 8.6 高度な生成（ベータ）の設定

「高度な生成（ベータ）」セクションで、[高度な生成](#高度な生成ベータ)の利用範囲と、AI による詳細分析を使えるかを決めます。このセクションは管理者だけに表示されます。

- **利用範囲**: 「全員」か「選択グループのみ」を選びます。部署を1つも選ばずに保存すると、管理者だけが使えます（管理者はいつでも使えます）。選べる部署は今ある部署だけです。保存したあとに消えた部署は「（見つからないグループ）」と表示され、誰にも当たりません。チェックを外して保存すると消せます
- **AI による詳細分析を許可**: 最初は OFF です。ON にすると、利用者の生成画面の詳細設定に「AI による詳細分析」が表示され、最初からチェックが入ります
  - **ON にする前に:** デプロイした環境（dev）で、AI による詳細分析を使った生成が最後まで通ることと、かかった時間・トークン数を確かめてから ON にしてください。AI が書いたプログラムを動かす仕組みは、実際の環境でしか確かめられない部分があるためです
  - **ベータの注意:** AI が書いたプログラムを動かす環境からは、AWS の一部のサービスに接続できます。AI にはネットワークを使わないよう指示していますが、仕組みで止めてはいません。利用者が信頼できるデータにだけ使う運用のときに ON にしてください（外部の人が書いた指示が入っているかもしれないファイルを扱うなら OFF のままにしてください）
- **保存**: 「保存」を押すと「保存しました。次に開いたページから反映されます」と出ます。変更は次に開いたページと、次に始めた生成から効きます。実行中の生成はそのまま最後まで動きます
- **同時に変えたとき**: ほかの管理者が先に保存していた場合は保存されず、「ほかの人が先に変えました。内容を確かめて、もう一度保存してください」と、最新の値が表示されます
- 最終更新者と時刻が表示されます

## 効果的な使用のためのヒント

### データファイルの準備

| 項目 | 推奨 |
|------|------|
| ファイル形式 | `.txt`, `.md`, `.pdf`, `.docx`, `.doc`, `.csv` |
| 内容 | 顧客の生の声、具体的なエピソード、調査データ |
| 構造 | 質問と回答が明確に分かれている（インタビューの場合） |
| 文字数 | 1,000文字以上 |

### 良いペルソナ生成のコツ

- データ内容は具体的で詳細なものを使用
- 複数の観点（価値観、行動パターン、課題など）を含める
- 「ペルソナ作成の指示」で特徴や条件を指定すると、より意図に沿ったペルソナが生成されます
- 生成後は必ず内容を確認し、必要に応じて編集

### 効果的な議論設定

- 異なる特性を持つ2〜5体のペルソナを選択
- 具体的で議論しやすいテーマを設定（例: 「新しいスマートフォンアプリの機能について」）

### マルチモーダルドキュメントの活用

| 対応形式 | 制限 |
|----------|------|
| 画像: PNG, JPEG | 個別5MB、合計32MB |
| ドキュメント: PDF | 個別10MB、合計32MB |

> 追加ペルソナベースモデル（GPT-5.6 Terra/Luna、Gemma 4 31B。管理者が有効化した場合のみ選択可能）でも
> Claude系と同様に画像・PDFの両方を添付できます。ただしGemma 4 31Bはリクエスト全体で3.5MBという
> 別の上限があるため、超過時はモデルを変更するか添付を減らしてください。

**活用例:**
- 商品画像やデザイン案を見せてペルソナの意見を聞く
- 競合製品の資料を参照しながら議論
- プロトタイプのスクリーンショットについてフィードバックを得る

> ⚠️ 機密情報を含むドキュメントの取り扱いには注意してください

### アップロード上限一覧とエラー時の挙動

機能ごとにアップロードサイズ・文字数の上限が異なります。上限を超えた場合、入力内容（選択済みの項目や入力済みの文章）は保持されたまま、フォーム近傍にエラーメッセージが表示されます（画面全体が消えたり、入力が失われることはありません）。

| 機能 | 上限 |
|------|------|
| ペルソナ生成ソースファイル | 10MB/ファイル |
| ペルソナ生成ソースの抽出後テキスト合計（複数ファイル合計） | 20万文字 |
| 議論・インタビューの画像添付 | 5MB/枚 |
| 議論・インタビューのドキュメント添付合計（画像+PDF） | 32MB |
| ペルソナの知識・事実ファイル添付 | 10MB以下、かつMarkdown変換後10,000文字以内 |
| ペルソナのアイコン画像 | 5MB以下、かつ JPEG は5,000万画素以下・PNG/WebP は1,600万画素以下 |
| システム設定のデータセット（CSV）アップロード | 10MB |
| マスアンケートのカスタムペルソナデータ（CSV） | 500MB |

対応していない拡張子（`.exe`、`.zip`等）をアップロードした場合もエラーメッセージが表示され、対応形式の一覧が案内されます。

アップロードしたファイルは、24 時間以内に議論やテンプレートで使わないと自動で削除されます。その場合はもう一度アップロードしてください。

> **補足**: 議論・インタビューの参考資料（画像・PDF）は、アップロード時点でブラウザ側の即時チェックが働き、形式やサイズが上限を超える場合はブラウザのポップアップで通知されます（この場合も選択済みのペルソナやトピック等の入力は保持されます）。それ以外の上限（モデル別の入力サイズ、ペルソナ生成ソース等）はフォーム近傍にインライン表示されます。

## セキュリティとプライバシー

- ペルソナデータ・議論結果はAmazon DynamoDBに保存
- アップロードファイルはS3バケット（設定時）またはローカルの`uploads/`に保存。ファイルは、読む権限のある人にだけ配信されます
- Amazon Bedrockとの通信は暗号化
- AWS IAMによるアクセス制御を適切に設定してください
- 機密情報を含むファイルの取り扱いには注意してください

## よくある質問（FAQ）

### モードについて

<details>
<summary>Q: 簡易議論モードとしっかり議論モードの主な違いは？</summary>

しっかり議論モードでは各ペルソナが独立したAIエージェントとして動作し、ファシリテータの進行管理のもとで順番に発言します。より自然で深い議論が可能になり、ペルソナの人格も一貫して維持されます。
</details>

<details>
<summary>Q: どちらのモードを使うべき？</summary>

迅速な意見収集には簡易議論モード、より深い洞察や自然な議論にはしっかり議論モードがおすすめです。
</details>

<details>
<summary>Q: しっかり議論モードで推奨されるラウンド数は？</summary>

まずは3〜5ラウンドを推奨します。1ラウンドでは浅い議論になり、10ラウンドでは時間がかかりすぎる可能性があります。
</details>

<details>
<summary>Q: ファシリテータの追加設定は必須？</summary>

いいえ、オプションです。デフォルト設定で十分機能しますが、議論の進行方法をカスタマイズしたい場合に使用してください。
</details>

### 長期記憶について

<details>
<summary>Q: 長期記憶機能とは？</summary>

ペルソナが議論を通じて学んだ内容を記憶し、将来の議論で活用できる機能です。Amazon Bedrock AgentCore Memoryを使用しています。
</details>

<details>
<summary>Q: 長期記憶を使用するには？</summary>

しっかり議論モードまたはインタビューモードで「長期記憶・知識を有効にする」チェックボックスをオンにしてください。システム管理者がAgentCore Memoryを設定している必要があります。
</details>

<details>
<summary>Q: 手動でペルソナに知識を追加できる？</summary>

はい。ペルソナ詳細画面の「知識・事実」タブから「知識・事実情報を追加」ボタンで、トピック名と内容を入力して保存できます。
</details>

<details>
<summary>Q: 長期記憶機能が使えない場合は？</summary>

環境変数`ENABLE_LONG_TERM_MEMORY`が`true`に設定されているか、`AGENTCORE_MEMORY_ID`が正しく設定されているか確認してください。
</details>

### 技術的な質問

<details>
<summary>Q: どのAIモデルが使用されている？</summary>

Amazon Bedrock上のClaude Sonnet 5.5（メイン）、Claude Haiku 5.5（しっかり議論・インタビュー・マスアンケートのデフォルト）を使用しています。しっかり議論・インタビューモードでは、ペルソナ・ファシリテータ毎にClaude Haiku 5.5 / Claude Haiku 4.5 / Claude Sonnet 5.5 / Claude Sonnet 5から使用モデルを選択できます。管理者が有効化した場合は、Bedrock Mantle経由でGPT-5.6 Terra/Luna、Gemma 4 31Bも選択可能です。
</details>

<details>
<summary>Q: データはどこに保存される？</summary>

ペルソナ・議論データはAmazon DynamoDBに保存されます。アップロードファイルはS3バケット（設定時）またはローカルの`uploads/`に保存されます。
</details>
